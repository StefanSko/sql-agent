The fault arena

Every injector has an expected externally visible result and an internal cleanup assertion. Repeat faults at multiple timing points.

Database6 FAULTS

Down before connect; disconnect mid-cursor; slow row; SQLSTATE with DSN-like text; lock timeout; 100k-row source.

expect: typed rejection + bounded memory + no secret
Model7 FAULTS

Malformed tool args; unknown tool; endless retries; parallel calls; duplicate final; output-only final; reasoning delta out of order.

expect: bounded retry + visible terminal state
SQL adversary6 FAULTS

Multi-statement; DML CTE; EXPLAIN ANALYZE DELETE; privileged file function; COPY PROGRAM; huge generate_series.

expect: reject before connect or DB defense
Stream5 FAULTS

Disconnect after tool start/result/partial text; interleaved call IDs; duplicate event; missing end event.

expect: state closes + cancellation propagates
History5 FAULTS

Orphan return; old matching answer; scalar substring; corrupted encrypted continuity; context threshold.

expect: valid resend or explicit refusal
Concurrency5 FAULTS

20 simultaneous runs; same thread IDs; mixed cancellation; slow and fast queries; shared trace pressure.

expect: isolation + no unbounded retention

Required telemetry

Instrument before faulting. Otherwise “the UI showed an error” can hide an active database cursor or model generation.

Request span

request ID, model rounds, tool call IDs, final terminal state.

Resource gauge

active tasks/connections/cursors, resident memory, retained result bytes.

Protocol log

ordered semantic events with redacted payload hashes.

Safety audit

pre-connect rejections, DB read-only rejections, SQLSTATE class, secret sentinel scan.

Decision rule
Typed core validatedif Pydantic variants contain more malformed-model and retry faults than the control without a safety or cleanup regression.
Simplification validatedif direct/SSE candidate matches or beats current stack in every safety round and improves cleanup/debug visibility or fault recovery.
Standards rescuedif MCP/AG-UI uniquely contain ordering, cancellation, concurrency, or replay faults that the “minimal” replacement mishandles.
Best contrary result: the full stack survives a fault class because a standardized lifecycle invariant exists, while the simple stack silently corrupts state. That is concrete capability—not abstract preference—and should reverse the relevant verdict.
