Run protocol

A balanced design makes each prompt its own control and rotates cell order to reduce warm-cache and model-drift bias.

01Freeze interfaces

One typed oracle, safety suite, event semantics checklist.

02Build adapters

Eight compositions behind identical runner inputs.

03Stratify tasks

Schema size, joins, ambiguity, multi-turn, held-out.

04Pair runs

Same case + seed across all cells; rotate order.

05Inject edges

Parallel calls, retries, truncation, malformed output.

06Estimate effects

Main effects, interactions, uncertainty, raw failures.

Measure more than speed

The verdict concerns behavior delegated and seams owned. Include correctness, containment, developer effort, and operational cost.

Outcome quality
  • typed-oracle correctness
  • held-out schema success
  • multi-turn fact retention
  • retry recovery
Safety
  • write attempts blocked
  • DSN never surfaced
  • bounded rows/time
  • safe failure text
Efficiency
  • model requests
  • input/output tokens
  • p50 / p95 latency
  • memory and payload
Ownership
  • nonblank adapter lines
  • defects per edge deck
  • change lead time
  • debug minutes

Analysis plan

Pairing by task and seed is more informative than comparing unrelated means. Preserve outliers instead of trimming framework failures away.

Primary model

Estimate paired differences with a mixed-effects or hierarchical model: architecture factors as fixed effects; prompt, schema, and seed as repeated/random effects. Report 95% intervals for A, B, C and A×B, A×C, B×C interactions.

  • Correctness: paired binary effect / non-inferiority
  • Latency and tokens: log-scale ratio
  • Defects: edge-case containment rate

Suggested scale

Start with 4 schema strata × 12 tasks × 5 seeds = 240 paired blocks, producing 1,920 total cell-runs. Pilot 10% first to estimate variance and runtime; do not use the pilot to tune thresholds.

  • One warmed model per block
  • Latin-square cell ordering
  • Fresh history and reset data
Decision rule · pre-register before running
Pydantic AI staysif it is non-inferior within 2 percentage points on correctness, has zero safety regression, and materially reduces boundary defects or maintenance time.
MCP stays locallyonly if it improves a measured consumer/maintenance outcome enough to offset added requests, seams, and dependency cost.
AG-UI staysonly if standardized lifecycle capability is used and its history/adapter defect rate is no worse than minimal SSE.
