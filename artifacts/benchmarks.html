Why did it win?

The catalog still crosses MCP. The optimization is where it happens: deterministic application setup replaces one or several model-mediated discovery rounds.

granular loop

Discover piecemeal

Model asks what tables exist, asks for descriptions, then reasons over accumulated returns. Bike-share median path: 6 requests; held-out path: 5.

→
catalog loop

Discover in one tool turn

One catalog call removes repeated descriptions. It saves two macro-median model requests and about 1.5k input tokens versus granular.

→
prefetched loop

Begin with typed context

The application obtains Catalog through MCP before inference. The model spends turns on SQL and correction—not schema acquisition.

Scope warning

Two tiny datasets, one local quantized model, three repetitions, and one machine do not establish a universal winner. Full Compose was implemented but not executed as a single topology because the machine lacked a Compose plugin and enough Docker VM memory for the model. The result supports this deployment shape; re-run the workload before generalizing.
